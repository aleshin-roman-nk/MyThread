# JChrono

Учебное full-stack приложение: ежедневные заметки по предметам. ASP.NET Core 10 раздаёт REST API и собранный Angular 21 с одного адреса; данные хранятся в SQLite через EF Core.

## Быстрый запуск

1. Клонируйте репозиторий и откройте папку проекта с файлом `start.cmd`.
2. Дважды щёлкните `start.cmd`. Если скрипт предложит установить недостающие инструменты через WinGet, введите `y` и подтвердите запросы установщиков. Скрипт соберёт сервер и Angular и запустит приложение. При первой сборке нужен интернет для NuGet и npm.
3. После запуска откройте [http://localhost:5080](http://localhost:5080).

Если WinGet недоступен или не смог выполнить установку, установите [.NET SDK 10](https://dotnet.microsoft.com/download/dotnet/10.0) и [Node.js 22.12 или новее из ветки 22](https://nodejs.org/dist/latest-v22.x/), затем откройте новый терминал и снова запустите `start.cmd`. В .NET SDK 10 уже входит ASP.NET Core Runtime 10. Скрипт также принимает .NET SDK новее 10 при наличии рантаймов .NET и ASP.NET Core версии 10 и поддерживает Node.js 20.19+ из ветки 20 и Node.js 24.

Файлы для отдельных операций:

| Файл | Действие |
| --- | --- |
| `build_server.cmd` | Собрать только сервер .NET, без запуска. Перед сборкой остановите сервер. |
| `build_client.cmd` | Собрать только Angular в `wwwroot`, без перезапуска сервера. |
| `run.cmd` | Запустить уже собранный сервер в фоне без видимого окна, без сборки. Повторный запуск не создаёт второй экземпляр. |
| `stop.cmd` | Остановить управляемый сервер. |

Если сервер уже запущен, повторный вызов `start.cmd` использует существующий экземпляр.
Чтобы пересобрать проект, остановите сервер через `stop.cmd` и снова запустите `start.cmd`.

Скрипты выполняются в открытой консоли: вывод сборки виден сразу. Сам сервер работает
в фоне без видимого окна, а его сообщения сохраняются в файлы журналов.
В конце каждого скрипта появляется зелёная надпись
`>>> ВЫПОЛНЕНИЕ СКРИПТА УСПЕШНО ЗАВЕРШЕНО <<<`, при ошибке — красная надпись об ошибке.
Консоль скрипта ждёт нажатия клавиши перед закрытием. Для запуска из терминала
или автоматизации без ожидания передайте `--no-pause`. В этом режиме `start.cmd`
требует заранее установленных инструментов.
PID и журналы `build_server.log`, `build_client.log`, `run.log`, `stop.log`, `stdout.log`, `stderr.log`
находятся в `artifacts/server/` (не попадают в Git). Журналы перезаписываются при запуске.
Вывод сервера записывается в `stdout.log`, ошибки — в `stderr.log`.
После перезагрузки Windows достаточно выполнить `run.cmd`.

Скрипт остановки проверяет PID, путь и время запуска процесса. Сервер, запущенный
через Visual Studio или вручную командой `dotnet run`, нужно остановить там,
где он был запущен; занятый порт 5080 не позволит запустить второй экземпляр.

При ошибке подробности видны в консоли и в соответствующем журнале в `artifacts/server/`.
Angular собран в `src/JChrono.Web/wwwroot`; отдельный Node.js-сервер при таком запуске не нужен.
Скрипт держит служебный кэш SDK/npm внутри проекта.

`build_client.cmd` переиспользует установленные зависимости. `npm ci` выполняется
при первом запуске, отсутствии `node_modules`, изменении `package.json`,
`package-lock.json`, локального `.npmrc` или версии Node.js/npm. Скрипт также
проверяет наличие Angular CLI и отпечаток установленного дерева пакетов.
Обычная повторная сборка выполняет только `npm run build`.
Для принудительной чистой установки используйте `build_client.cmd --reinstall`;
параметр можно сочетать с `--no-pause` в любом порядке. Если отдельные файлы
внутри `node_modules` повреждены вручную, используйте `--reinstall`.
При публикации по-прежнему выполняется чистая установка через `npm ci`.

## Как пользоваться

1. **Добавьте предмет.** Откройте «Предметы», введите название и короткое имя до 8 символов, например «ASP.NET» и `DEV`, затем нажмите «Создать предмет».
2. **Запишите первую заметку.** На странице «Мой день» нажмите «Новая заметка», выберите предмет, введите текст и нажмите «Сохранить заметку». На этой странице можно выбрать дату и посмотреть записи дневника и сессии за день. Чтобы собрать идеи по теме, откройте «Заметки предмета» на его странице.
3. **Разбейте работу на задачи.** На странице предмета откройте «Проекты» и нажмите «Новый проект». Откройте созданный проект, перейдите к списку задач и нажмите «Новая задача».
4. **Учитывайте время.** На странице предмета нажмите «Начать сессию». После занятия завершите её. Время работы за выбранную дату видно на странице «Мой день».
5. **Планируйте занятия.** В разделе «Планирование» выберите день в календаре, нажмите «Добавить занятие» и укажите время начала и длительность.
6. **Держите важное под рукой.** Закрепляйте нужные заметки на «Рабочем столе» или создавайте там текстовые стикеры.

## Архитектура

### Сервер .NET

Сервер организован по vertical slices. Срез соответствует одной операции API, а срезы сгруппированы по областям: `Diary`, `Planning`, `Sessions`, `Subjects`, `Projects`, `Notes` и `Desktop`. Задачи входят в `Projects`, статистика и журнал сессий — в `Sessions`.

```text
src/
  JChrono.Domain/                   Сущности и доменные правила
  JChrono.Application/Features/     Обработчики операций, DTO и контракты доступа к данным
  JChrono.Infrastructure/Features/  Запросы и хранилища на EF Core и SQLite
  JChrono.Web/Features/             HTTP-контроллеры отдельных операций
  JChrono.Web/DependencyInjection/  Регистрация обработчиков и хранилищ по областям
tests/JChrono.Tests/                Интеграционные тесты xUnit
```

Границы проектов сохранены. `Application` зависит от `Domain`, `Infrastructure` реализует контракты `Application` и работает с доменными сущностями, а `Web` связывает обработчики с реализациями. `Domain` и `Application` независимы от EF Core и ASP.NET. В `Program.cs` вызываются методы регистрации из `DependencyInjection/`. Там же настраиваются HTTP-конвейер и раздача Angular. Общие для хранилищ `NotesDbContext` и `DatabaseInitializer` находятся в `Infrastructure`.

Например, `GET /api/diary/notes` принимает `ListDiaryNotesController` из `Web/Features/Diary`. Обработчик `ListDiaryNotes` из `Application/Features/Diary` проверяет период и вызывает `IDiaryNotesQuery`. Реализация `ListDiaryNotesQuery` из `Infrastructure/Features/Diary` читает SQLite. Регистрация `AddDiary()` связывает контракт запроса с реализацией.

### Клиент Angular

```text
client/src/
  main.ts         Запуск Angular и регистрация маршрутизатора
  app/
    app.component.ts  Оболочка приложения
    app.routes.ts     Сборка маршрутов в порядке сопоставления
    features/         Страницы, компоненты, API и загрузчики по областям
    shared/           Общие компоненты, директивы, сервисы и утилиты
```

В `features/` находятся `day`, `diary`, `planning`, `statistics`, `desktop`, `subjects`, `projects`, `tasks`, `notes` и `sessions`. HTTP-запросы сгруппированы в сервисах соответствующих областей, например `DiaryApi`, `NotesApi` и `SessionsApi`. `SessionState` в `features/sessions` хранит состояние текущей сессии. Загрузчики страниц предметов, проектов, задач и заметок находятся рядом с их компонентами. Маршруты вызывают их через `resolve.page`, а общий тип результата `PageResult` находится в `shared/`.

Определения маршрутов лежат в `*.routes.ts` соответствующих разделов, а `app.routes.ts` задаёт общий порядок и перенаправляет неизвестные адреса на `/`. «Мой день» (`/`) входит в начальную сборку. Дневник, планирование, статистика, рабочий стол и страницы предметов, проектов, задач и заметок загружают компоненты по запросу через `loadComponent`. При прямом открытии адреса страницы ASP.NET отдаёт `index.html`, после чего маршрут обрабатывает Angular.

### Предметы, проекты и заметки

Сущность `Note` представляет заметки дневника, предметов, проектов и задач. Все виды хранятся в таблице `Note`. Записи из прежних таблиц переносит `DatabaseInitializer`. Название предмета занимает 1–100 символов и уникально после обрезки пробелов без учёта регистра. Текст заметки занимает 1–4000 символов. Заметки предмета сортируются по дате, времени и идентификатору от новых к старым.

Заметка дневника содержит календарную дату, время и оценку от 1 до 5. Режим «День» показывает время на карточках и сортирует их от утра к вечеру. В режиме «Месяц» карточки сгруппированы по датам.

У предмета есть короткое имя длиной 1–8 символов и коллекция проектов. Проект ссылается на предмет и содержит название (1–200 символов), код (1–64 символа) и коллекцию задач. Задача ссылается на проект, имеет название (1–200 символов), код (1–64 символа) и описание (1–20000 символов). Коды уникальны без учёта регистра внутри родителя: проекта — внутри предмета, задачи — внутри проекта. Короткие имена и коды не допускают слешей и управляющих символов. Полные коды вычисляются из родителей и разделяются ` \ `; изменение короткого имени предмета сразу отражается во всех полных кодах.

## Разработка

После правок фронтенда выполните `build_client.cmd` и дождитесь сообщения о завершении.
После правок сервера выполните по очереди `stop.cmd`, `build_server.cmd`, `run.cmd`,
дожидаясь сообщения о завершении после каждого действия.

Angular уже настроен собирать HTML, JavaScript и CSS непосредственно в
`src/JChrono.Web/wwwroot` (`outputPath` в `client/angular.json`), поэтому
копировать файлы вручную не требуется. После сборки фронтенда обновите страницу
на порту 5080 (при необходимости Ctrl+F5). На время обновления файлов возможны
ошибки загрузки страницы; дождитесь сообщения о завершении сборки.
`build_client.cmd` сам сервер не запускает — для запуска используйте `run.cmd`.

Для ручной сборки клиента из корня проекта выполните в PowerShell:

```powershell
cd client
npm.cmd ci --no-audit --no-fund
npm.cmd run build
```

Если зависимости уже установлены и `package-lock.json` не менялся, достаточно `npm.cmd run build` из `client/`.

Для пересборки Angular при изменениях запустите в отдельном терминале:

```powershell
cd client
npm.cmd run watch
```

Обновите страницу на порту 5080 после пересборки. Альтернативный режим с автоматическим обновлением: `npm.cmd start` в `client/`, интерфейс на порту 4200, запросы `/api` проксируются в ASP.NET на 5080. Дополнительный сервер нужен только для разработки.

Для интеграционных тестов сервера выполните из корня проекта:

```powershell
$env:DOTNET_CLI_HOME = Join-Path (Get-Location) '.dotnet-home'
dotnet restore tests/JChrono.Tests --configfile NuGet.Config
dotnet test tests/JChrono.Tests --no-restore -c Release
```

При повторном запуске с восстановленными пакетами выполните последнюю команду из блока. Тесты поднимают ASP.NET через `WebApplicationFactory` с временными SQLite-базами. Среди проверок — фильтры, валидация, HTTP-статусы, транзакции и конкурентные запросы. Данные пользователя хранятся отдельно.

## SQLite и конфигурация

По умолчанию файл: `src/JChrono.Web/App_Data/notes.db`. Он не попадает в Git. Новая база создаётся через `EnsureCreatedAsync`. `DatabaseInitializer` при запуске транзакционно обновляет исходную схему: добавляет короткое имя предмета, таблицы проектов и задач с индексами и состояние проекта, сохраняя существующие данные. Старые предметы получают короткое имя `S` + ID (до 8 символов); его можно заменить на странице предмета. Существующие проекты получают состояние «В работе». Повторный запуск безопасен и сохраняет уже установленные состояния. Это обновление исходной схемы, а не общий механизм EF migrations; для следующих изменений схемы расширьте обновление или внедрите миграции, не смешивая `EnsureCreated` с `Migrate` для существующей базы.

Путь можно переопределить перед запуском:

```powershell
$env:ConnectionStrings__Notes = 'Data Source=D:\Data\jchrono.db'
.\run.cmd
```

Относительный путь считается от content root ASP.NET. Каталог базы создаётся автоматически. Для резервной копии остановите приложение и скопируйте базу вместе с существующими файлами `-wal` и `-shm`.

## Нумерация проектов и задач

Сервер присваивает коды `0001`, `0002` и далее. Нумерация проектов независима
в каждом предмете, задач — в каждом проекте. В предмете хранится `LastProjectNumber`,
в проекте — `LastTaskNumber`. Увеличение счётчика и создание объекта выполняются
в одной транзакции, включая конкурентные запросы. Неудачное создание откатывает
счётчик. Закрытие, архивирование и удаление не уменьшают счётчики: номера удалённых
объектов не выдаются повторно. Внутренние ID БД независимы от кодов.

Пользователь не вводит и не меняет код. Четыре цифры — минимальная ширина:
после `9999` идёт `10000`. Максимум — `99999999`; при исчерпании сервер возвращает 409.
Старые коды сохраняются. При первом добавлении счётчиков они инициализируются
по наибольшему числовому коду внутри родителя, включая архивные записи;
нечисловые коды не участвуют. Повторный запуск не пересчитывает счётчики.

## Учебные сессии

Доменная сущность `Session` хранит обязательный предмет, необязательные проект и задачу,
полные дату и время начала и конца (`DateTimeOffset`, UTC) и текст до 1000 символов. Текст можно оставить
пустым. Если передана задача без проекта, используется её проект; все связи должны
относиться к одному предмету и проекту.

При открытии сервер записывает начало, конец отсутствует. Статус вычисляется:
`EndTime == null` — `Open` (0), иначе `Closed` (1); отдельного столбца статуса нет.
Текущая сессия выбирается по отсутствию конца без отдельной таблицы. Уникальный
индекс на константу `1 WHERE EndTime IS NULL` допускает только одну открытую сессию,
включая конкурентные запросы. Попытка создать или повторно открыть вторую возвращает 409.
При закрытии сервер записывает конец. Начало, конец и текст можно редактировать и у
закрытой сессии; обнуление конца открывает её повторно. Конец не может быть раньше
начала. Поля начала, конца и текста участвуют в проверке конкурентности сохранения.

Сессия может продолжаться через полночь и несколько дней. `Duration` вычисляется
как разница конца и начала и не хранится в БД; для открытой сессии она отсутствует.
Для итоговой статистики нужно суммировать интервалы закрытых сессий по `SubjectId`;
индекс `(SubjectId, StartTime)` подготовлен для выборок по предмету и началу сессии.

Таблица `Sessions` обновляется при запуске без удаления данных. Старые сессии с
раздельными датой и временем переносятся как закрытые; прежнее время трактуется
в локальном часовом поясе сервера и сохраняется в UTC. При обновлении схемы с хранимым
статусом столбец статуса и запрещающий правки триггер удаляются, все сессии сохраняются.
На странице предмета кнопка «Начать сессию» открывает сессию текущего предмета
с серверным временем начала. Сессии показаны от ранних к поздним и восстанавливаются
после обновления страницы. Доступны завершение и модальное окно правки времени и текста.
Пока есть открытая сессия, начать другую нельзя; для сессии другого предмета показана ссылка.
Кнопка «Проекты» открывает страницу со списком проектов предмета, фильтрами по статусу
и месяцу создания и кнопкой «Новый проект».

На странице проекта доступен тот же блок сессий с выбором даты, завершением,
правкой и удалением. Новая сессия связывается с проектом и его предметом.
На странице проекта отображаются только его сессии; на странице предмета они
также входят в общий список сессий этого предмета. В заголовке «Текущая сессия»
ведёт к проекту, если сессия создана для проекта.

## Публикация в каталог

```powershell
$env:DOTNET_CLI_HOME = Join-Path (Get-Location) '.dotnet-home'
$env:npm_config_cache = Join-Path (Get-Location) '.npm-cache'
dotnet restore src/JChrono.Web --configfile NuGet.Config
dotnet publish src/JChrono.Web --no-restore -c Release -o artifacts/publish
dotnet .\artifacts\publish\JChrono.Web.dll --urls http://localhost:5080 --contentRoot "$PWD\artifacts\publish"
```

`dotnet publish` автоматически выполняет `npm ci` и сборку Angular, затем включает `wwwroot` в результат. На целевой машине нужны ASP.NET Core Runtime 10 и права записи в каталог данных; Node.js после публикации не требуется. `-p:SkipClientBuild=true` используйте только если актуальный Angular уже собран.

Это локальный однопользовательский пример без авторизации. Для размещения в сети сначала добавьте аутентификацию, разграничение доступа и HTTPS.
